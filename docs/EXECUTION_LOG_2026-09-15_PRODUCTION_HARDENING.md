## 7. Explicit Railway `npm ci` and discovered Corepack failure

Railway documentation identifies `RAILPACK_INSTALL_CMD` as the supported custom install-command override. Production service variable was set on each canonical application service:

`RAILPACK_INSTALL_CMD=npm ci --no-audit --no-fund`

Affected services:

- `growth-os`;
- `migrator`;
- `growth-os-publication-worker`.

The resulting PR #168-lineage redeploys all failed during image packaging, not dependency installation or TypeScript compilation. Representative failure:

`copy /opt/corepack`

`lstat /opt/corepack: no such file or directory`

The failure reproduced across all three canonical services. This isolated the problem to the Railpack 0.39 Corepack packaging route created by the combination of explicit `packageManager` and custom install command.

Previous successful deployments remained the serving production version while these replacement deployments failed.
